# 結果を返すために出したページだけ、確認欄なしで送る (#3591)

## 目的
#3583 の確認欄は、計画ページのように「選んで返す」ためのページでは毎回の手間になる。そのページだけ、送信ボタンでそのまま会話へ届くようにする。

## 仕組み
- `presentHtml` の新しい引数 `submit: "direct"`。`submitModeFor`（`src/core/submitMode.ts`、純粋関数）が、`html` で書いたページのときだけ結果の `data.submit` に乗せる。`path` で開いたページには付かない。
- View（`useHtmlSubmit`）は `mulmo-html-submit` を受けると `deliveryFor(mode, lastDirectAtMs, nowMs)` で届け方を決める。
  - `direct`：すぐ `sendTextMessage` を呼び、「会話に送りました」を短く出す。
  - `confirm`：今までどおり確認欄に出す。印の無いページ、または直前の直接送信から `DIRECT_SUBMIT_MIN_INTERVAL_MS` 以内の送信。
- 送信の失敗：ホストの `sendTextMessage` が `false` を返したら、内容を確認欄に残して失敗を出す（直接送信・確認欄の送信の両方）。戻り値を返さない古いホストは成功とみなす。

## 文書ごとの鍵（レビューで足した）
- 印付きのページを出すとき、View は iframe の URL の `#mulmo-submit-key=<使い捨て>` に鍵を載せる。ページは送信に `key` を添える。鍵が無い・違う送信は確認欄に回す。
- リンクやスクリプトで iframe が別の文書へ移ると URL の `#` は引き継がれないので、移った先の文書（読み込み途中で送ってくるものも含む）は鍵を持たない。
- iframe は `:key` を結果と URL で決めるので、結果が替われば要素と Window ごと作り直され、古い文書が積んだメッセージは送り元の照合で捨てられる。

## 信用の範囲（レビューで明記）
- 印付きのページ自身は信用する。そのページのスクリプトは、確認なしで何でも送れるのと同じなので、鍵を `window.name` や自分で組み立てた URL で後の文書へ渡すことも止めない（止めても新しくできることを防いでいない）。
- 守るのは、そのページが意図せず別の文書に移った場合（リンク、リダイレクト）。リンク先の URL には鍵が付かないので、移った先は鍵を持たない。

## 決めたこと
- `path` を外すのは、よそ由来の HTML（クローンしたリポジトリ、ダウンロード、build のレポート）が開いただけで、ユーザーのメッセージとして指示を出すのを防ぐため。
- 連続送信は捨てずに確認欄へ回す。不具合で連打するページでも、会話を埋めず、内容も失わない。
- iframe の再読み込みでは直前の送信時刻を戻さない。読み直しを繰り返すページで歯止めを外させないため。

## 残るリスク
エージェントが読んだものに乗せられて、印付きで「開いたら送る」ページを書く場合は防げない（印を付けるのがエージェント自身のため）。

## 範囲外
- MulmoClaude はツールの実行を自前でしているので印が乗らず、確認欄のまま。
- 計画の skill で印を付けるのは MulmoTerminal 側。
